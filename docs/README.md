# Unica Documentation

Normative architecture and engineering specifications for `@docouno/unica`. Read these core concept guides before designing, implementing, or reviewing components.

During design, use these constraints to define appearance and the intended accessible experience. The [Workbench workflow](workbench.md#design-outcome-and-prototype-behavior) separates that design result from the complete library API and interaction mechanisms implemented in the next stage. Native behavior may support the preview without making it a production component.

## Core Concepts

| Document | Scope |
| --- | --- |
| [Themes and Roles](concepts/themes-and-roles.md) | Flat CSS tokens, token tiering, `ThemePreset` metadata, the three reference themes (`Soft`, `Frost`, `Pixel` in `Dark`/`Light`), role-based component props vs decorative `appearance` props, and strict semantic color rules. |
| [Geometry and Layout](concepts/geometry-and-layout.md) | Parametric `Control` vs `Surface` radius scales, `--radius-factor`, concentric inner-radius math ($R_{\text{inner}}$), `0px` degeneration in `Pixel` (preserving circular `Radio`), monotonic Z-elevation (`AppRail < Aside < Main Canvas < Card`), numeric `Spacing`, and unified `s / m / l` sizing. |
| [Feedback and Errors](concepts/feedback-and-errors.md) | `status` vs `tone` vs `color` vocabulary, four feedback channels (`FormField`, `Toast`, `Alert`, `Empty`), strict `<FormField>` ownership across three canonical compositions, and `Combobox` vs `Autocomplete` value authority. |
| [Component Anatomy](anatomy.md) | Canonical `packages/ui/src/components/<Family>/` structure, master axis dictionaries, `data-unica-*` flags, single-hyphen classes, and automated conformance gates. |
| [Native Scrollbars](concepts/scrollbars.md) | Shipped native scrollbar utilities for ordinary surfaces and overlays, including system fallbacks. |
| [Overlays and Forms](concepts/overlays-and-forms.md) | Native browser top layer (`popover="auto" | "manual"`, `<dialog>` `showModal()`, toast host above active modals, positioning adapter) and native `<form>` participation (`FormData`, `reset`, `disabled`/`readOnly`/`loading`, controlled vs uncontrolled authority). |
| [Support and Accessibility](concepts/support-and-accessibility.md) | Two-tier browser support floor (`Guarantee` vs `Baseline`), React 19 pure-ESM contract, WCAG contrast invariants, keyboard navigation, `forced-colors`, and `prefers-reduced-motion`. |

## Workbench & Component Contracts

- **Interactive workbench & compositions:** `apps/playground` hosts the component inspector. Catalog entries live in `src/specimens/`. Visual prototypes live in `src/prototypes/` and compositions such as [Folio](compositions/folio.md) in `src/scenes/`.
- **Specimen authoring:** [Workbench workflow](workbench.md) explains the component schema, live inspection, scene links, and deterministic screenshots.
- **Browser contracts:** [Browser tests](browser-tests.md) explains offline Chromium runs and how to add scenarios for native browser behavior.
- **Component contracts:** [Accordion](components/accordion.md) and [Collapsible](components/collapsible.md) cover in-flow disclosure, focus, and form lifecycles. [Alert](components/alert.md) covers persistent feedback and dismissal. [Avatar and AvatarGroup](components/avatar.md) cover portraits, fallbacks and compact member lists. [Badge](components/badge.md) covers inline status, counts, and native actions. [Blockquote](components/blockquote.md) and [Code](components/code.md) cover quotations and inline literals. [Button and IconButton](components/button.md) cover native actions, toggle and loading states, and button-shaped links. [Card](components/card.md) covers content surfaces, media, and navigation. [Chip and ChipGroup](components/chip.md) cover wrapping single- and multi-select facets. [Divider](components/divider.md) covers static boundaries and connecting phrases. [FormField](components/form-field.md) covers field labels, feedback, and group associations. [Icon](components/icon.md) covers SVG sources, adapters, sizing, and accessibility. [Indicator](components/indicator.md) covers corner counts, activity dots, and host semantics. [Input](components/input.md) covers single-line editing, validation feedback, and native forms. [NumberInput](components/number-input.md) covers native numeric drafts, decimal stepping, and exact form payloads. [Kbd and KbdGroup](components/kbd.md) cover keyboard hints and accessible chord notation. [Layout](components/layout.md) covers the six responsive primitives and `VisuallyHidden`. [Link](components/link.md) covers native and router navigation. [Tooltip](components/tooltip.md) and [HoverCard](components/hover-card.md) cover control hints and read-only link previews. [Popover](components/popover.md) covers anchored non-modal dialogs, focus, and forms. [Portal](components/portal.md) covers host resolution, SSR, and hydration. [Scrollbar](components/scrollbar.md) covers native scroll owner utilities. [SegmentedControl](components/segmented-control.md) covers compact single-choice groups and native form behavior. [Skeleton and SkeletonText](components/skeleton.md) cover decorative loading placeholders. [Slider and RangeSlider](components/slider.md) cover stepped numeric editing, native forms, and two-thumb ranges. [Spinner](components/spinner.md) covers local activity and reveal timing. [Progress and ProgressCircle](components/progress.md) cover measurement, waiting phases, and accessible labels. [Tag and TagGroup](components/tag.md) cover removable values, disclosure, and keyboard focus. [Textarea](components/textarea.md) covers native multiline editing and form integration. [Text](components/text.md) and [Title](components/title.md) cover semantic typography.
- **Commands:** [Menu](components/menu.md) provides button-anchored commands, links, immediate settings, and adaptive submenus. [ContextMenu](components/context-menu.md) adds pointer, keyboard, and touch invocation on an object.
- **Binary controls:** [Checkbox](components/checkbox.md) covers independent and mixed selections, [Radio](components/radio.md) covers single selection and group navigation, and [Switch](components/switch.md) covers immediate settings and pending operations. Each family includes a group and a decorative indicator. [Choice cards](components/choice-card.md) cover richer labels, independent secondary actions, mixed compact/card membership, and native forms.
- **Catalog choices:** [Listbox](components/listbox.md) keeps choices visible in the page flow. [Select](components/select.md) puts the same choices in an anchored field with optional search. Both cover single and multiple selection, availability, and native forms.
- **Contributor workflow:** [`../AGENTS.md`](../AGENTS.md) defines workspace commands, Devkit rules, and Definition of Done gates.
