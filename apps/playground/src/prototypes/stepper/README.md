# Stepper design reference

Open `?item=stepper` in the workbench. The reference covers an ordered process with a short sequence of named stages, such as setup, migration, or onboarding. The map can be read-only or let people revisit completed stages and repair stages with an issue. The enclosing flow owns step content, Next and Back actions, validation, and confirmation. Use Progress to describe the measured work inside a stage.

## Anatomy and layout

Compose the named `Stepper` with ordered `StepperStep` entries. Each entry has a marker, a required short title, an optional description, and corrective text when it needs attention. The ordinal is the one-based position in the supplied order. Text wraps naturally, including long words, keeping the title and corrective text visible. Use short, distinct action labels and one brief description per stage. An empty sequence renders no map. A one-stage sequence has no connector.

| Size   | Marker | Marker glyph and numeral | Title   | Gap from marker to copy, horizontal / vertical | Gap between entries, horizontal / vertical |
| ------ | ------ | ------------------------ | ------- | ---------------------------------------------- | ------------------------------------------ |
| Small  | 24px   | Caption L                | Body XS | 8 / 8px                                        | 12 / 20px                                  |
| Medium | 32px   | Body S                   | Body S  | 8 / 12px                                       | 16 / 24px                                  |
| Large  | 40px   | Body M                   | Body M  | 8 / 16px                                       | 24 / 24px                                  |

Medium is the default. Icon glyphs occupy 1.15 times the numeral's font size. The descriptions and corrective text use Caption L with a 2px gap. Vertical copy aligns its first title line with the marker center. This keeps wrapped copy attached to its own stage. Touch expands interactive entries and the compact disclosure to at least 44×44px at supported widths. Static entries keep the same 44px minimum row height so a stage becoming current does not move its neighbors.

- **Horizontal.** The default layout at 36em or wider in the component's own inline size, based on the current Body S font size. Choose it explicitly where the containing page guarantees room for the labels. Equal-width columns align the markers, rail, and first title lines. Use the available width, with the first marker flush to the surrounding content edge. Connectors run from the end of one marker to the start of the next, with an 8px gap at each end.
- **Vertical.** A persistent map for side panels, narrow columns, or longer copy. The markers and the vertical connectors form one column. Longer text gives the row more height and the incoming and outgoing rails keep their alignment. This layout is selectable at any width.
- **Compact.** The default below the horizontal threshold and an explicit option where space is limited. Show equal-width decorative segments on an 8px track, with 4px gaps. The current segment is 8px high and all others are 4px. Below the track, show the ordinal and total, the current title and any description or corrective text. List each other stage that needs attention by name with a danger glyph and secondary text. With no current stage, show the count of valid completed stages out of the total, or “All steps complete.” When return is enabled, the All steps button opens the same ordered map vertically, inline below the summary, with a 16px gap. While open, the header retains the current position and title. The ordered map carries the details and the accessible reading order. Closing restores the detailed summary without resetting any steps.

Keep distribution, reading, and tab order aligned to logical inline-start. In RTL the horizontal map, connectors, compact segments, and button placement mirror. Vertical order and ordinal values stay the same. Text scales with the theme type tokens and the responsive threshold moves with Body S.

## State and material

| Condition                    | Marker                                                  | Title and feedback                             | Can activate when return is enabled                                      |
| ---------------------------- | ------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------ |
| Future or gated              | Neutral outline and ordinal                             | Secondary title, muted description             | No                                                                       |
| Completed                    | Neutral raised fill and check                           | Secondary title                                | Yes                                                                      |
| Current                      | Solid accent and ordinal, with a 1px accent signal edge | Semibold primary title                         | No                                                                       |
| Needs attention              | Danger tint and exclamation-in-circle                   | Corrective text below the optional description | Yes when a different stage is current, or when there is no current stage |
| Current and needs attention  | Same danger tint, edge, and exclamation glyph           | Semibold primary title and corrective text     | No                                                                       |
| Revisiting a completed stage | Current marker and title                                | Its completion stays recorded                  | Other completed stages remain available if return is enabled             |

Current, completion, and need for correction are independent. A stage with an issue uses danger paint and is excluded from the completed count even if it was complete earlier. Returning to an earlier stage leaves other stages' completion and issues intact. If an edit changes downstream validity, the flow supplies the updated states. A workflow can have no current stage before starting, after taking a break, or after completing every stage. The map retains the supplied facts in each case.

Use a 1px rail at the marker center, quiet by default. Use a stronger neutral for a connection whose origin is complete and whose destination is complete or current. A connector never stands alone as a status cue. A stage with an issue breaks outgoing emphasis, even when it is current. The step immediately before a current stage with an issue can still show its completed approach.

Markers use the contextual control fill and border for upcoming stages, a raised neutral fill for completed stages, the semantic accent pair for the current stage, and the danger soft pair when correction is needed. The line, contours, and underlines stay subordinate to the surrounding task and its primary button. The current marker uses a single silhouette. The valid current stage uses the accent signal on its 1px edge. All stages that need attention share the same 1px danger edge, tint, and glyph. The current stage retains its semibold title and taller compact segment. Soft paints matte. Frost gives the valid current marker a static, local accent bloom via `--_stepper-current-shadow` (10px blur at 42% accent signal in Dark, 8px at 25% in Light). The numbered face and danger state stay crisp. Pixel uses crisp 0px corners. The map sits directly on its host surface. On a floating surface, the host supplies the backdrop, border, and shadow.

## Interaction and accessibility

- Name the ordered list's group by the workflow. The full map exposes one `aria-current="step"` where applicable, each stage's title and ordinal, completion, and corrective text. The collapsed compact summary exposes the current stage. The segments are decorative.
- When return is enabled, the marker, title, description, and corrective text form one button for each eligible stage. A 1px title underline at 60% of the label ink distinguishes these actions at rest. Hover sharpens the underline and tints the marker. Press deepens the tint without shifting the marker, copy, or rail. Keyboard focus adds a 2px outline with a 2px offset around the marker and strengthens the underline. The compact disclosure uses the same contour on its button frame. This applies to actual native input and is pinned in the interaction example for visual comparison.
- Tab and Shift+Tab visit eligible buttons in reading order. Enter and Space request that stage, using a non-submit button. Stepper's disclosure is a separate native button for showing the map and carries its expanded state. The read-only map and its compact summary have zero tab stops. Current and gated entries have a static pointer treatment.
- The enclosing flow accepts or declines a stage request. If keyboard activation makes a step current and the map remains mounted, put programmatic focus on that stage and show the same 2px focus ring with a 2px offset from the marker. Tab continues in order. Pointer activation leaves the new current marker treatment without a persistent keyboard ring. A declined request leaves focus with the original action. A flow that replaces the view should focus the heading of the new stage. For changes triggered by external controls, the enclosing flow owns focus and any milestone announcements.
- Opening the compact map keeps focus on All steps, which precedes the stage buttons in tab order. Activating a stage from the expanded map keeps the map open. If a wide map narrows while a step has focus, keep the compact map expanded and retain that focus. If widening hides the focused disclosure, move focus to the current step, the first available return action if there is no current step, or the list itself if neither exists. This responsive focus handling belongs to library implementation.
- State changes and disclosure are immediate. The marker and rail stay in place during press, and changing stages never animates a marker along the rail. With forced colors, outlines, glyphs, dash treatment for segments with issues, current marker treatment, and system focus remain visible independently of backgrounds and shadows.

## Workbench and implementation handoff

- **Horizontal sizes** and **Vertical sizes** compare all three marker sizes, a dense row with titles alone, and longer descriptions beside a vertical rail. **Step layouts** compares the four projections of the same workspace map.
- **Progress and validation** shows the stages before starting, two stages with issues, a revisited completed stage, a saved five-stage setup and a finished process. **Long stages in a narrow column** and **Compact summaries** keep wrapped descriptions and saved or invalid states visible at constrained widths.
- **Return to a step** starts with hover, press and focus on three eligible stages. Pointer or keyboard interaction switches to live feedback. Compare how focus behaves when the owner accepts or declines the request.
- **Workspace setup** opens on access rules with workspace details already complete. Continue to reveal the missing owner, revisit the completed details, then assign yourself as the owner and confirm the workspace. Each new action requires a separate activation. The compact map and action buttons can also be used with a surrounding form.
- **In a floating surface** places the same map on a theme overlay surface. Folio's **Workspace Admin & Batch Import** is a separate consumer with a passive map and task controls below it. The dry run clears the staged validation work in this local preview, enabling the commit stage. Changing the inputs invalidates that result.

The examples supply local state and simulated outcomes. The library handoff includes stable stage identity, localization of generated text, a single accessible projection at each width, a complete focus lifecycle for accepted and declined requests and reflow, and browser-level verification. Preserve the visual and behavioral decisions above when designing the public React API.
