# Tabs design reference

Open the [Workbench](../../../../../docs/workbench.md#inspect-components-and-scenes) with `/?item=tabs`. Use Matrix for Horizontal, Vertical, and Icons and counts. Cases covers Selection and feedback, Overflow and distribution, Manual activation, and On a floating surface. Folio's [Document Reader and Rich Editor](../../../../../docs/compositions/folio.md) show the in-product fit.

## Scope and anatomy

Tabs switch between peer panels within a single view. One available tab owns selection, its panel is the only visible panel, and a short accent rule identifies the selected tab. Use SegmentedControl for an input value, NavList or Link for routes, and Accordion for independently open sections. Open-document management in TopRail has its own document lifecycle.

| Part        | Responsibility                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tabs        | Groups a named tab list and its panels. Owns selection, orientation, size and activation policy.                                                                                         |
| TabsList    | Lays out the row or column. Owns horizontal overflow and contributes a single keyboard stop through its tabs.                                                                            |
| TabsTab     | A button with a text label, optional leading icon, optional trailing count, and an edge marker when selected. Icon-only buttons require an accessible name and the matching visual hint. |
| TabsContent | One panel per tab. The component provides the tab relationship, active visibility, and panel semantics. Consumers supply what goes inside.                                               |

Horizontal is the default and usually sits above the panel. Vertical fits views with a persistent local rail and room to read its labels. `orientation` sets the list axis, selection rule position, and arrow keys. The consumer lays out the list and panel with Grid or Flexbox and owns their widths, gap, surface, and responsive placement. In the Vertical specimen the layouts give the list up to 120px, 160px, and 192px, with 12px, 16px, and 24px column gaps. The last example places a full-width panel below the rail when the artboard is 420px or narrower. The vertical list and its arrow keys stay vertical in that layout. A consumer can also choose a horizontal list at narrow widths. In RTL the rule, slots, and logical layout mirror.

## Geometry and slots

| Size | Button height | Inline padding | Slot gap | Leading icon | Label type                                | Equal minimum |
| ---- | ------------: | -------------: | -------: | -----------: | ----------------------------------------- | ------------: |
| S    |          30px |           10px |      6px |         14px | Small control font on body-xs line height |          78px |
| M    |          40px |           16px |      8px |         16px | Body S                                    |          96px |
| L    |          48px |           20px |     10px |         20px | Body M                                    |         112px |

Sizes describe the button itself. There is 4px between buttons and a 4px inset around the strip for the focus outline. Labels keep weight 500 across all states. Minimum height allows text to grow. Use 44px minimum targets on coarse pointers. An icon-only tab starts from a square target matching the size height and remains centred. Use it for a familiar view glyph. A visible text label is preferable for unfamiliar or consequential destinations.

The leading icon inherits the label ink. Vertical rows with leading icons reserve the same icon column for neighbouring text rows. Counts follow text in horizontal tabs and sit at the trailing edge of vertical rows. Use a passive neutral S Badge with tabular numerals and a quiet foreground veil over the local surface. The count stays visible if the label truncates. Omit absent counts, render meaningful zero, and let the product choose a visual cap such as `99+`. Decorative counts can be hidden from the accessible name. Supply meaningful counts in words, with the exact value when the visible count is capped, as in “History, 104 pending reviews”. Icons in labelled tabs are decorative.

### Distribution and overflow

- Every vertical tab row fills the available rail width inside the focus clearance, at S, M and L. Pointer and touch activation cover the whole button, including the space after the label. Row labels align to inline-start and icon-only rows centre their glyph. The surrounding layout sets the gap between the rail and panel. Content and Equal distribution apply to horizontal lists.
- **Content** sizes each horizontal tab to its contents. A standalone label is limited to 36ch. Evaluate the row at its natural width before reserving room for chevrons. If the row overflows, cap individual tab widths to the clear space between the controls, any fade, and the 4px focus clearance. A fitting row uses the full available width for labels.
- **Equal** fills the horizontal strip with equal cells. For horizontal strips of 360px or less, Equal caps inline padding at 12px. Cells reserve 7ch for a short label, or 8ch when the row has icons or counts, plus the inline padding and room for the largest icon and count combination. The count budget is 3ch plus 10px and a slot gap. If the resulting cells cannot fit, keep their widths and scroll.
- Responsive distribution can change at the list's own available widths of 768, 1024 and 1440px, with a mobile default of Content. Omitted steps inherit the preceding value. The responsive specimen stretches three tabs below 768px and shows their natural widths above it. Orientation stays stable as width changes.
- Keep horizontal tabs in one row. A fitting row shows all tabs directly. Overflow uses native inline scrolling with edge controls in the same row. The browser's horizontal scrollbar has no painted track or gutter here.
- Use a neutral ghost chevron only on a side with more content. Each control sits over a clear area the width of its target. Soft and Frost add a 12px fade from that area into the row, revealing the owning surface. Pixel clips the row at the straight edge of the control area. Forced colors and increased contrast also use the straight edge. The controls overlay the viewport without changing tab widths, label positions or strip height. When both sides can scroll, both controls appear. Their direction and placement mirror in inherited or locally set RTL. A count crossing the clear area's boundary, including any fade, is hidden as a whole, with its slot and accessible wording preserved. On coarse pointers the controls have at least 44px targets.
- Click or tap a chevron to advance the viewport, keeping 24px of context when space allows. Swipe or horizontal trackpad scrolling also browses the row. Browsing preserves the selection and the panel. Reduced motion makes the chevron step immediate. The chevrons are named controls outside the tablist. Keyboard users browse with the existing arrow keys, Home and End, so the chevrons add no sequential tab stops.
- Focusing or choosing a tab reveals its full target and 4px focus clearance beyond any overlaid control or fade, with immediate local scrolling and no page jump. Keep keyboard focus fully visible when width or distribution changes. Reveal the selection after layout settles until the user begins browsing. Preserve manual scroll position outside keyboard navigation. Focusing or choosing a tab interrupts an in-progress chevron step.
- Single-line labels ellipsize at their own end while icons and counts retain their width. On available tabs with an icon-only or truncated label, [Tooltip](../../../../../docs/components/tooltip.md) shows the full string on hover or keyboard focus. Escape dismisses the hint and leaves focus on the tab. Scroll hides the hint if its anchor leaves the viewport. Use short, recognizable labels on disabled tabs and preserve their full accessible name. Touch selects directly and reads the full destination in the panel when the tab uses a long or icon-only label.

## Material and state

Selection uses primary label ink and a single 2px accent rule. In horizontal tabs it sits at the block-end of the button, inset from each actual button edge by half of its used inline padding. For example, a 128px button with 16px padding on each side carries a 112px rule. Content and icon-only buttons use the same inset rule. Equal-width buttons extend the rule as the cell grows. Vertically the 2px rule sits at logical inline-start, inset 8px from the top and bottom of the row. The selected label, icon, count and button geometry remain steady on hover and press.

Soft uses terracotta and Frost uses violet, with rounded ends on the rule. Pixel has cyan accents, square ends, and JetBrains Mono. The canvas or overlay remains visible around the labels. The containing toolbar, panel or layout owns any structural divider. Apply 4px corners to the neutral pointer feedback and focus contour in Soft and Frost, and square corners in Pixel.

Unselected tabs have a transparent fill and muted legible text. Hover restores primary ink and adds a 4% foreground veil. Held press uses an 8% veil. Soft transitions the neutral veil over 110ms, Frost over 130ms, and Pixel responds immediately. Disabled peers use disabled ink, including the count. Selection and panel updates are immediate. Reduced motion also removes the neutral veil transition.

Keyboard focus alone draws the shared 2px outline at a 2px offset. Manual activation can show that outline on one tab while the accent rule stays under another. Pointer interaction leaves focus paint to the browser's input-modality behavior. Forced colors use CanvasText for labels, a 2px Highlight rule for selection and a separate Highlight outline for focus. Hover uses LinkText and a text underline. A held peer uses Highlight with HighlightText, and unavailable labels use GrayText.

## Input and panel outcomes

- Name the list and pair each `tab` with a labelled `tabpanel`. Keep a single entry stop on the current available selection. Arrow navigation wraps and skips disabled items. Left/Right move along the horizontal row and mirror in RTL. Up/Down move along a vertical column in either direction. Home and End go to the first and last enabled item. Perpendicular arrows keep their native page behavior.
- Automatic is the default for ready, immediate panels. Arrow movement both focuses and selects. Manual fits expensive panels and keeps them unchanged during arrow navigation until Enter, Space or click commits. Both modes keep focus on the tab after selection. Reactivating the current tab leaves its state alone. Tab exits the strip in document order. When the active panel immediately follows the list, focus goes to the panel or its first focusable content. Adjacent controls in the same toolbar remain in document order. Shift+Tab follows that order back through the strip.
- Treat a programmatic selection as a panel change. Reveal the selected tab when focus is outside the strip, leaving that external focus alone. If hiding/removing a focused panel or changing the tab set would strand focus, recover to the current available selection before the next paint. With no explicit initial selection, use the first enabled tab. If an uncontrolled selection is removed or disabled, choose the next enabled item in order, then the previous one if there is no next item. Controlled owners provide a valid available selection for the new set together with the update. With no available views, surface the empty state at the owning screen.
- Default panel content stays mounted and hidden with native `hidden` whenever inactive. A library lazy strategy mounts on first selection and then retains state. An unmount strategy resets that panel's contents each time it is left. All modes preserve tab-to-panel ID relationships and keep hidden content out of keyboard travel and the accessibility tree. The active panel can be a focus stop when its first meaningful content is static. Panel loading, errors and empty states belong to panel content. State changes leave the strip stable.

The Workbench runs real clicks, arrow navigation, manual commitment, panel switching, chevron scrolling, and full-name hints. It uses stable sets, eagerly mounted content, and the package Tooltip for truncated and icon-only tabs. The Selection and feedback case pins hover and held press for comparison. Use Tab and the arrow keys in the live controls to examine focus and its relationship to selection. Library lifecycle for dynamic sets, focus recovery, mount policies, and the public React API are defined in the implementation wave.

Carbon gives line tabs lower visual emphasis than contained tabs and uses a trailing divider where the layout benefits from it. Atlassian combines active underlining and quiet peer labels with a separate divider. Primer's UnderlinePanels keep panel switching and count slots in this restrained pattern. For Unica, the inset rule marks the selected button in the Folio toolbar and inspector and on the contained Overlay surface.
