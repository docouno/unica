# AppShell and workspace navigation design reference

Open the [Workbench](../../../../../docs/workbench.md#inspect-components-and-scenes) at `/?item=app-shell`. Matrix shows rail combinations and compact panel entry points. Cases cover live document navigation, responsive panels, settings and save behavior. Open `/?item=app-shell&tab=cases&block=responsive&family=all&scheme=both&vp=1280` to try all four combinations of dock visibility across the six presets. Set the frame to 360px to try the native touch targets and sheets. Usage shows five shell topologies. The [Folio scenes](../../../../../docs/compositions/folio.md#explore-the-live-compositions) exercise the same shell across a document workspace, editor, settings and administration.

## Workspace frame

| Part              | Geometry and purpose                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TopRail           | A 46px minimum row for brand, search or open documents, and contextual actions. The desktop brand cell is 56px and lines up with the side rail. A brand cell without content disappears. Document tabs, the all-documents button and the add action share one centerline. Larger controls may grow the row. The search example uses the shared S Input with a search icon and the standard pointer and keyboard focus treatments.                         |
| LeftRail          | A 56px strip with 36px desktop destinations and 6px spacing. The top group holds destinations and the bottom group holds utility and account. The brand is in TopRail for the L-shaped layout and in LeftRail for the classic layout. Each icon has an accessible name and the desktop tooltip uses the existing Tooltip treatment. Unread counts are passive and announced in the action name.                                                           |
| AsidePanel        | A docked navigation or inspector panel. Starting measures are 243px at inline-start and 296px at inline-end. Rich inspector content can ask for 360px. Header, scrolling body and optional footer have separate ownership. The header uses a 48px minimum with leading identity and a wrapping title or a tab list. Header actions stay outside the tab list. The footer has a single separating rule.                                                    |
| Stage and canvas  | Canvas is the reading and editing plane and may contain elevated cards. When TopRail and LeftRail meet, the stage starts with a 1px seam, 14px outer and 13px inner corners in rounded themes, and square corners in Pixel. The corner keeps its shape when Navigation collapses. A lone side rail uses a straight seam. Each boundary has one border. Either aside can be omitted or docked alone. Standalone uses the canvas without peripheral chrome. |
| Header and Subbar | The canvas header starts at 48px with a breadcrumb or title and a separate action group. Subbar starts at 44px for same-level filters, formatting or view controls. Each bar grows with the text and groups may wrap at narrow widths. Items keep their own focus and activation semantics.                                                                                                                                                               |

Outer chrome uses `--bg-shell`, the aside uses `--bg-aside`, the canvas uses `--bg-canvas`, and cards use `--bg-surface`. The four planes step up in luminance across all six presets. Soft keeps close, matte steps with warm accents. Frost keeps clear indigo separation and opaque docked planes. Pixel keeps straight edges, mono rhythm and crisper structural rails. Docks and sticky bars are opaque. Reserve blur and stronger elevation for the modal sheet and floating controls. Chrome stays still on press. In navigation, the neutral feedback eases over 110ms in Soft and 130ms in Frost, with immediate feedback in Pixel and under reduced motion.

### Responsive and scrolling behavior

- A dock can be shown or hidden independently. Navigation keeps its ghost IconButton at inline-start of the canvas header. An open Inspector places its Hide button at inline-end of the aside header. A hidden Inspector puts its Show button at inline-end of the canvas header, separated from page controls by a 16px vertical Divider. The Inspector button and glyph keep the same position and size across both states. Both header slots share a 12px inline-end inset and center the button in the first 48px header row, excluding the bottom rule. Each slot reserves space for its action, including when a title or toolbar wraps. Both actions use a small ghost IconButton with a Show or Hide label, a Tooltip and an expanded state. Focus follows the visible control. Hidden docks release their canvas space and preserve selection, scroll and draft values. For a supplied header, compose the chrome with `Header` to enable the dock controls. An omitted header uses the controls-only header when a dock needs it. A rail-only layout keeps its rail and shows the compact Navigation entry below 540px.
- With a shell at least 1100px wide, both asides can dock. Between 800px and 1099px, the inspector becomes an overlay while navigation can stay docked. From 540px to 799px, either aside is opened by a labelled control and the side rail stays visible. Below 540px, the side rail joins Navigation. When there is also an inline-start aside, its body stays the primary navigation and a “Workspace sections” disclosure reveals the named global destinations. In a rail-only shell the named destinations show directly. Missing slots produce no trigger.
- A compact Navigation Drawer enters at inline-start. An Inspector Drawer enters at inline-end. Both mirror in RTL and leave a visible sliver of scrim. They keep a clear Close target in the header, focus the named heading on entry and confine keyboard travel. The first Tab reaches Close. The sheet uses safe-area insets and the theme-owned rim and shadow. Close and Escape restore the opening control. Navigation also closes on a primary press and release on the backdrop. Inspector keeps the backdrop protected while editing. The shared Drawer entry pairs 20px of travel from the attached edge with a 200ms fade. Its scrim fades over 150ms. Close returns focus immediately, and reduced motion removes entry motion. Choosing a document completes navigation, closes the sheet and places focus on the new main view. Widening past the docking breakpoint closes the modal, keeps the panel's state and moves focus to main if the trigger disappears.
- In a bounded shell, the canvas and each aside body own their real, independent scrolling. TopRail, Header/Subbar and aside header/footer stay in sight. A Drawer scrolls as one surface when less than 96px remains for its body. In document flow, the page owns canvas scrolling. Use the Compact [native scrollbar utility](../../../../../docs/concepts/scrollbars.md) for aside bodies, bounded canvases, the sheet scroll owner and the all-documents list. Desktop Chromium and Safari show a 4px thumb in a 10px gutter. Track and corner stay transparent. Only actual overflow paints a thumb.
- The keyboard-accessible Skip to content link appears on focus and moves focus to the canvas. Use a main landmark in a standalone shell. Workbench previews use named canvas regions within the Workbench main landmark. Desktop chrome follows normal document tab order. At coarse pointer sizes, use larger targets for row activation and sheet controls. In forced colors, selection and focus have independent system outlines, and scrollbars use the system recipe.

| DocumentTabs                       | These are open workspace destinations with a document lifecycle. Each destination gets its own link or local activation button and the current document has `aria-current="page"`. A peer panel switch uses [Tabs](../tabs/README.md). The document strip stays on one line. A canvas-colored plate and primary ink mark the current item. A dirty dot is separate from the close target and announced in the name.                                                                                                                                                                                                                                                                                                                                                                                      |
| Pinned, long and crowded documents | Pinned items sort to the leading edge and scroll with the strip. They have a pin glyph and their full names remain available in the tooltip and the all-documents list. Titles over the local 92–176px cap ellipsize. The tooltip and overflow list show the full title. The strip keeps native inline scrolling through touch, trackpad and keyboard focus with the scrollbar hidden. “All open documents” opens an anchored Popover list showing current, pinned and dirty status. It opens above the trigger when room below is tight, tracks its anchor on scroll and resize, and limits its height to the visible window. Opening the list focuses the current item or the first entry. Selecting an entry reveals and focuses that item in the strip. The add action remains outside the viewport. |
| Closing and opening                | Close is a separate 30px small ghost IconButton (44px on touch) and never activates the document. Delete on a local document switcher is an equivalent shortcut. Close buttons stay visible regardless of hover. Dirty close asks before discarding. Cancelling preserves the document and focus. On close, reveal and focus the next surviving item or the previous one at the end. Change the current document only when that document closes. Opening a new document focuses its current tab. Closing the last document restores focus to the Add action at the leading edge. Any explanatory text lives in the canvas. A pinned tab omits Close in the strip. Managing the pin belongs to the document owner.                                                                                        |

## Settings rows and save bar

**SettingsRow** connects a wrapping label, optional help and status to a standard control. **PropertyRow** uses the same geometry for compact inspector metadata or an inline `ghost` control. There is a 16px inactive gap in the two-column layout and the trailing control takes 44% of available width. The control moves below the label at 248px of row-container width, or 285px when the row has supporting text. Stacked controls have an 8px gap and up to 220px of width. Read-only values are text or a read-only control. Disabled controls keep their context with explicit “Managed” feedback where appropriate. Errors pair a status with a message connected to the control. Labels and descriptions wrap, and an inert gap stays inert. Hover, focus and validity paint belong to the control.

**StickyActionBar** appears within the scrolling canvas at block-end, inset 16px. It has an opaque raised surface, standard surface radius, 1px rim and restrained contact shadow. The summary has room to wrap. A trailing primary save and lower-priority discard action stack as a group when the message and controls no longer fit side by side. The bar stays within the canvas. The scroll owner reserves clearance so the focused field can be revealed above the bar.

| State              | Expected result                                                                                                                                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Clean              | Dirty-only layouts can remove the bar. Persistent layouts can show a quiet “All changes saved” confirmation with inactive actions.                                                                                     |
| Dirty              | Show that changes are unsaved and enable Save and Discard. A newly visible bar does not take focus from the field.                                                                                                     |
| Saving             | Keep the bar mounted and reserve the action position. The save control shows progress, both actions prevent duplicates, and assistive technology receives a status update.                                             |
| Failed             | Preserve edits and show an explicit error and Retry. Keep Discard available. Restore the dirty or clean state after the user resolves the error. The outer rim signals the error without tinting the whole foreground. |
| Saved or discarded | Commit the current draft or restore the last acknowledged values. Return focus to the edited field if its triggering action disappears or becomes disabled. An in-progress save must not be presented as discarded.    |

## Zero-surface layout geometry

The layout studies use the shipped [Layout primitives](../../../../../docs/components/layout.md). The examples keep their local guides, surfaces and gutters.

| Primitive         | Design                                                                                                                                                                              |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Box               | Structure and token-based spacing. Consumers choose whether its content owns a visual surface.                                                                                      |
| Flex              | One-axis row or column with independent align, justify, wrap and gap. Preserve DOM order.                                                                                           |
| Stack             | Column-oriented spacing for flows with a single block axis.                                                                                                                         |
| Grid and GridItem | Equal flexible tracks use `minmax(0, 1fr)`. The example chooses a valid item span for each visible track count. Use one, two, three or four columns as the content space permits.   |
| Container         | Centered 720, 960 or 1280px maximum measure, with fluid 12–32px inline gutters in this example. Content below the maximum fills the available measure without horizontal scrolling. |

Responsive layout values follow CSS viewport breakpoints at 768, 1024 and 1440px. Omitted steps follow their nearest preceding value. Resize the browser to switch these values. Workbench frame width shows how the current layout fits its container. AppShell docks its regions against the shell width. Geometry uses logical properties, the system spacing scale and native CSS. Native `hidden` removes an item or primitive from both layout and focus. Guides and cells in the specimen are example content.

## Prototype boundary

The search field demonstrates the shared Input and accepts text locally. Search results belong to the consuming workspace. The responsive study includes independent dock controls and native modal behavior, and the two smaller frames pin the open navigation and inspector layouts for comparison. The settings study runs local save, discard, pending and retry states. The document study runs local switching, overflow, creation and confirmation. Folio Preferences scrolls inside a bounded canvas, keeping actions in reach while a preference changes. Folio breadcrumbs, workspace destinations and open-document links preserve the selected Workbench family, scheme, width, text scale and direction as the scene changes. Generic examples use local selections. Production routing, dirty-data persistence, reusable focus/scroll integration, and the public React contract belong to library implementation.
