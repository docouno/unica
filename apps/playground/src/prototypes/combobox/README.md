# Combobox design reference

Open `?item=combobox` in the workbench. The role matrix and Team assignment are interactive. Sections marked **pinned** keep states side by side for inspection. The Page Properties drawer in Folio provides the reference for a compact reviewer picker inside an inspector. Its composition can use the same field and panel.

## Purpose

Combobox selects one catalog entity by stable ID. Search happens in the same field that displays the selected label. Use Select when the field should be a closed trigger with optional search inside the popup. Use Autocomplete for unrestricted text. Use TagsInput for multiple free-form entries. Creation of catalog entities and selection of multiple entities use their own product flows.

## Field and results

- Default is the Input form slot. Ghost keeps its transparent surface and straight baseline, including when the panel is open. Labels and support copy wrap as in FormField. An optional leading search glyph is decorative. The status glyph and search spinner sit before Clear and the disclosure chevron. Clear reserves a slot when enabled for the field. The chevron has a local neutral hover plate, an open plate, and a stronger edge on press. Read-only fields display a lock, retain readable and selectable text and status, and hide editing actions. Disabled fields take precedence over status and loading.
- S/M/L field heights are 30/40/48 px. The shell inherits Input padding, glyph sizes, field radii, and focus contours. The chevron target is 24/24/28 px for fine pointers. L grows its clear and disclosure targets to 44 px for coarse pointers. Use L in primarily touch-driven forms. The text viewport stays single line and ellipsizes at rest, then scrolls with the focused caret. Auto width caps the pairing at 20 rem. Full width follows its container.
- The result panel uses the small shared Popover material, 4 px shell inset and the shared option viewport's 4 px inset. Its logical start aligns to the field with an 8 px gap. Width is the larger of the field and 264 px, limited to the visible viewport with 16 px edge clearance. It opens below when there is room, flips above when there is more room, and stays on that side while usable so changing results do not bounce the popup. The scroll area shrinks to the available height, up to 22 rem. Scroll inside the popup while leaving the field and recovery bar fixed. Lose the anchor and the panel closes.
- Options use the Listbox row anatomy and typography. Group labels and supplementary option descriptions wrap. An optional leading icon column aligns labels across groups. Very narrow panels (15 rem or less of content width) omit decorative result icons to protect label width. Text keeps its own direction and aligns to the reading column. The trailing check column is reserved in every row. The committed option uses the accent check with ordinary text, and navigation or hover uses the neutral plate. A row can show both at once. Press deepens the plate without moving its contents. Unavailable entries stay visible, with a useful explanation when available, and never receive an active plate. If the application explicitly marks the committed option unavailable, the check remains visible and the application can explain the change or require a replacement. A filtered or unloaded option remains a valid selection with its retained label. Never show a raw ID in the field.
- Soft uses a matte field and opaque raised results. Frost uses the inherited overlay fill, rim and backdrop blur without painting a second panel behind the options. Pixel uses square corners, the Popover's hard offset shadow and corner marks, and the theme's monospaced type. Field status affects the field and its message. The panel stays neutral. Opening, closing, and navigation are immediate in all materials. Only the search spinner animates, with a static glyph in reduced motion. Forced colors retain a visible field focus, the selected check, and a system-highlight active-row edge.

## Replacement and recovery

| Moment                                             | Visible result                                                                                                                | Answer                                                                                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Reopen a confirmed field with the arrow or chevron | Full catalog with a check by the confirmed entity. The field still shows its label.                                           | The confirmed ID remains valid.                                                                         |
| Edit any part of that label                        | Search results and a quiet pending-selection bar with **Restore previous selection**. The field has a concise neutral prompt. | No ID is submitted while replacing it. The previous ID and label remain available for recovery.         |
| Escape, Tab, or click elsewhere                    | Panel closes. Keep the exact draft and show the labeled restore action under the field.                                       | An unfinished draft stays unconfirmed, including a draft equal to an option's label.                    |
| Explicit validation                                | Explain how to resolve the unconfirmed answer in the normal danger message. Keep the restore action.                          | An unfinished answer fails validation. An optional field with an explicitly cleared answer stays empty. |
| Restore                                            | Close the list and return focus to the input with the previous label and ID.                                                  | Restore from the snapshot without a search.                                                             |
| Clear                                              | Clear the input and close the panel. Return focus to the empty input.                                                         | Clear the answer, query and recovery snapshot together. A new search starts from empty.                 |
| Choose a result                                    | Close the panel and return focus to the input with the new label.                                                             | Confirm the new ID and replace the recovery snapshot.                                                   |

The recovery action lives in the panel header while open. Dismiss the panel to reach it in the regular Tab order under the field. This keeps the input and its editing controls usable in compact layouts. The same words identify the action in both locations. The header wraps across lines as needed. Status messages use the normal FormField spacing without repeating the pending prompt when the validation error already explains the next step.

## Search feedback

Keep the text editable during loading. Clear or restore can abandon a pending query. Show the spinner in the field and **Searching…** with a short reassurance in the panel. Remove previous-query results when pending or failed. A threshold shows **Type to search** with the minimum when configured. A completed unmatched query shows **No matches** and a corrective hint. An empty unfiltered catalog and a result set with every entry unavailable have separate messages. Fetch failure keeps the draft, uses a restrained warning glyph, and gives a way forward in words. These messages sit outside the selectable list, use normal legible text, and should be announced politely without becoming an active result. The result list marks itself busy during a search. The recovery bar continues to offer Restore when there is no selectable result and labels the replacement as pending. Explanations for unavailable rows remain readable. An application owns search timing, invalidation of stale responses, and any external retry policy.

## Input and accessibility

The editable input maintains DOM focus while the popup is open. Keep the input's system focus treatment and draw the neutral active plate with a subtle edge on a result. ARIA identifies the input as a list-autocomplete combobox, describes whether it is expanded, and references only a visible enabled active descendant. The pointer chevron is excluded from Tab order. Ordinary focus alone does not open results. Typing, arrow keys and the chevron open the panel. Typing and disclosure open with no active row. The first arrow starts at the confirmed row if enabled, otherwise at the first or last enabled row in the arrow's direction. Further arrows skip unavailable rows, stop at the edges, and scroll the active row into view without scrolling the page. Browsing preserves input text. Enter applies an active result and consumes that Enter. Enter with no active result closes the panel and follows the form's normal validation or submission path, leaving any validation message in view. Space, Home, End and horizontal arrows keep their ordinary text-editing behavior. IME composition uses native editing and must finish without choosing a result or submitting the form. Escape dismisses suggestions first, including within a Drawer. Tab and outside dismissal never accept a suggestion. Restore and Clear have local focus contours when reached by keyboard.

The live form demonstrates assignment validation and recovery without a network. Pinned states are in-flow material studies. They do not claim top-layer placement or real focus. The live prototype uses a manual popover and local keyboard and pointer behavior. Production implementation supplies the stable-ID form carrier, reset, controlled state, validation, live announcements, cross-browser focus and IME, and scroll behavior within nested overlays. Reset should return to the initial ID and label and clear any open query and recovery history. Read-only keeps its answer for submission and disabled omits it.
