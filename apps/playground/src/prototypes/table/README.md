# Table design reference

The visual and interaction design was approved on 2026-11-19. Open `/?item=table` in the Workbench for the prototype and implementation reference.

The Table family compares records along two axes in plain documents, bounded registries, cards, and overlays. The prototype provides nine native parts for captions, row groups, rows, and cells. The scroll viewport is a companion.

| Density & alignment       | The same three columns at 32, 40, and 48px. Region labels sit in the center, and request counts and their total line up at the logical end.                                                                               |
| Editable rows             | Edit a route or choose a policy, then restore that row from its actions menu. The system route shows a copyable read-only value and a disabled picker.                                                                    |

## Layout and material

The caption is the visible name of a standalone table. It is set in medium body text with a 12px gap below. A nearby heading can name a table that is part of a larger section. Use column headers for attributes and a row header for the label that identifies each record. Put a link inside the row header when the record has a destination. Keep commands in their own cells. Selection controls live in a narrow leading column and actions in a narrow trailing column. Center both. Use a cell with a real checkbox for page selection, with an accessible name that states its scope. Each row checkbox names its own record.

| Density                 | Minimum single-line row | Inline padding per cell | Block padding per cell | Body / header type  |
| ----------------------- | ----------------------- | ----------------------- | ---------------------- | ------------------- |
| Compact (`s`)           | 32px                    | 10px                    | 5px                    | Body XS / Caption L |
| Standard (`m`, default) | 40px                    | 16px                    | 8px                    | Body S / Body XS    |
| Comfortable (`l`)       | 48px                    | 20px                    | 10px                   | Body M / Body S     |

Rows expand for their tallest cell, wrapping, and text scaling. A touch-primary pointer raises the baseline to 48px and provides at least 44px sort and selection targets. Embedded controls also need a 44px target in that layout. Use logical start, center, and end consistently across each column. Comparison figures use tabular numerals. Units belong in the header where all rows use the same unit. Isolate values with mixed text direction. Paragraphs and identifiers can wrap, including long unbroken strings. Keep short, scan-critical metadata and its headers together and give intrinsically wide tables a minimum width inside their own scroll viewport.

The owning surface shows through. A table uses horizontal 1px rules, with a stronger header and totals seam. Soft and Frost use quieter body rules. Pixel uses the stronger rule throughout and gets square controls from its theme radius. There is no table perimeter, cast shadow, column grid, or resting row hover fill. The optional stripe applies to alternate visible body rows using 3.5% foreground over the owning surface. Unavailable rows retain readable content, with only the scoped control disabled. An explicitly opened row context menu gives its source a 7% foreground wash. A selected row replaces either wash with the theme's selection paint. The checked indicator is the non-color signal. The wash remains behind badge, link, and focus feedback. Forced colors retain system rules, the checkmark, and an inset Highlight outline on the selected row.

Sticky headers belong to a bounded table viewport and travel with it on the inline axis. The table keeps an opaque ground below the entire header and a single hairline below the labels. On canvas the ground matches the canvas. Inside a Card it matches the card role. In an overlay it uses an opaque ground matched to the panel. Frost uses a calibrated solid tone close to the glass. Text from scrolling rows stays fully covered. A visible caption scrolls away. The footer stays at the end of the data.

Table uses the [compact native scrollbar](../scrollbar/README.md#native-geometry-and-density) on both axes. On desktop Chromium and WebKit, a 4px thumb sits in a transparent 10px gutter. Firefox and touch-primary browsers use the native `thin` width. The browser displays the bar for actual overflow and places it according to the current direction.

## Interaction and state

- **Sort.** A static label is plain text. A sortable label has a permanent double caret in the idle state and a single directional caret when sorted. The sorted label uses primary ink and the caret uses accent. The caret stays adjacent to the label and its footprint stays fixed. At logical end the caret precedes the label so the label and figures keep the same reading edge. Hover and press darken or lighten the control in place, with no travel. The 2px keyboard contour fits within the header inset. Native focus stays on the same button as sorting changes. Only the active header exposes `aria-sort`. The demo cycles ascending, descending, and source order. The application owns its actual sorting policy, data, and result announcements.
- **Select.** Space toggles the focused independent checkbox. The header is unchecked for none, mixed for some, and checked for all eligible rows in the current range. Mixed activates selection of the eligible rows. Checked clears that range. Unavailable rows are excluded from the count and bulk operation. Focus remains on the checkbox used. Selecting a row neither opens the record nor invokes its menu. Sorting keeps selected records attached to their identities.
- **Actions.** The named overflow trigger stays visible. Rows with a context menu offer the same choices through the trigger or by right-clicking a neutral area of the row. Keep native context actions on text selection, links, and editors. Escape returns focus to the invocation control. When scrolling takes an open menu's anchor entirely out of view, dismiss the menu and move its keyboard focus to the scroll region. The row stays available for text selection and stays outside the tab sequence.
- **Inline fields and row actions.** Ghost Input, Select and the trailing `⋯` share a 3px block inset inside the cell's rule and 4px on the inline edges. Their desktop surfaces are 25, 33, or 41px high for S, M, or L. Fields fill the remaining cell width, with their labels aligned to the column headers. The icon trigger is square in a dedicated column. Select and `⋯` use the same quiet plate on hover and while open. The keyboard contour sits inside each control. Coarse pointers increase the control surfaces to 46px and let the row grow around them. An editable text control has a single local baseline in 66% muted ink. A read-only text cell uses a lock and keeps its value copyable. Choosing a value updates the same cell without a row-height jump. The picker opens over the scrollport and restores focus to its trigger. Application-specific validation, submit, and persistence follow the owning form.
- **Scrolling.** An overflowing wrapper is a named region and a tab stop. A fitting wrapper has neither role nor extra tab stop. Keep the wrapper's outline visible outside its edge. Tab visits the existing links, sort buttons, fields, and row controls in reading order. Native scrolling works with the pointer, touch, and the focused scroll region. Reveal the full focused control and its contour on both axes. Keep body focus below a sticky header, including when tabbing backward or returning from a menu. Keyboard focus does not add a whole-row selection treatment.
- **Data state.** Keep columns visible while an application loads, filters to zero, or fails. The loading example reserves rows with Skeleton and marks the table busy. The preview Retry switches to this state and moves focus to the persistent preview control. An empty result uses a single spanning cell with Empty. An error uses a single spanning cell with Alert and an adjacent recovery action. Keep live status outside the busy area. Paging belongs beside the scroll viewport, so it remains available on a narrow screen without an inline scroll.

Visual changes in the table itself are immediate. Adjacent controls and placeholders keep their own reduced-motion and forced-colors behavior. The example sorting, selection, field editing, menus, scrolling, and two-page index work locally. Result states are controlled previews, and the Drawer is the existing bounded Workbench preview. Wave 2 owns the final React API and the reusable observation and keyboard details. The design uses native table navigation and delegates data, interaction policy, and any spreadsheet experience to the consuming application.
