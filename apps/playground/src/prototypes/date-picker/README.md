# Calendar, DatePicker & DateRangePicker — design reference

Status: design candidate, pending visual approval. Open `/?item=calendar`, `/?item=date-picker`, or `/?item=date-range-picker`. The existing collection and document-properties scenes consume this family. These are visual prototypes; their helper props, state storage and DOM are not a proposed package API.

## Purpose and boundaries

Calendar is a frameless Gregorian date grid for one day or an inclusive continuous period. It embeds in a page, card, drawer or picker panel without adding another surface. DatePicker adds one ordinary editable text input and a compact single-month panel. DateRangePicker keeps both dates in one text input and uses the same single-month panel to select a complete period. Calendar alone supports consecutive months (1–12) and a twelve-month year overview. Picker panels always show one month.

Use a date field for an exact date, a range field for one complete interval, and separate DatePickers for independently meaningful dates in separate form rows. Time, time zones, recurring schedules, non-Gregorian calendars, disconnected selections, booking-specific checkout rules and application shortcut presets are outside this family. The app can compose shortcut actions beside the picker. There is no Apply / Cancel row, decorative panel variant, weekend color, week-number gutter or nested month-selector popover.

## Anatomy and geometry

Calendar contains a previous/next navigation header, separate text buttons for month and year, weekday labels and exactly six week rows. Adjacent-month positions are empty noninteractive placeholders; dates never appear twice in a multi-month view. The root has no border, fill or shadow. Digits use tabular figures. Day buttons have a transparent resting background and a theme-derived control radius. All geometry uses logical inline directions.

| Metric                    | S              | M              | L              |
| ------------------------- | -------------- | -------------- | -------------- |
| Calendar cell             | 32px           | 40px           | 44px           |
| Single-month width        | 224px          | 280px          | 308px          |
| Day face                  | cell minus 4px | cell minus 4px | cell minus 4px |
| Date field minimum height | 30px           | 40px           | 48px           |
| Day type                  | body-s         | body-m         | body-l         |

Week rows are separated by 4px. Weekday labels have a 24px minimum row. The header is at least 32px, followed by 12px. The month and year labels are separate controls. Each opens its own three-column, four-row selector in place of the day grid. Picking a month keeps the year. Picking a year keeps the month where permitted; a boundary year opens the nearest in-bounds month. Either choice returns directly to days or to the year overview and leaves the selected value intact. Choosing a month or year preserves the focused day of month where possible. Escape restores focus to the originating label.

The picker panel is 282px wide on fine pointers. It uses a medium surface radius, 12px padding, 8px section gaps and a 36px day pitch. Standalone Calendar retains its own S/M/L sizing. It has the containing Popover material: contextual overlay tokens, rim, backdrop and shadow. Both panels open directly on the calendar, with month and year navigation above the days. The panel is named for assistive technology and has an explicit close button in the footer. The single-date footer offers Today when it is available. The range footer prompts for the next date, or shows the proposed duration while the user previews an interval. The prompt names the first chosen date between selections. Calendar errors appear in the same footer. A valid final day confirms the choice immediately. Month names and labels wrap rather than overlap navigation.

Multi-month layouts wrap columns at the cell-based month width, with a 24px gutter. The year overview uses S density and the same six-week geometry. On desktop, three columns group the year by quarter, reducing to two and then one as space narrows. Touch columns use the full 308px month width. There is no horizontal month-strip scrolling. At coarse pointers, days and calendar navigation are at least 44 × 44px and the panel expands to 336px. At small viewport heights the panel remains within viewport margins and scrolls vertically; implementation must account for the visual viewport and keep the focused control visible. On a 360px screen the panel can occupy the viewport with 8px margins, independently of a narrow trigger. Opening with the calendar button must not summon the software keyboard.

## Material and state hierarchy

Soft uses warm or cool matte surfaces, rounded day faces, solid selected endpoints and soft ribbons. Frost uses the containing glass surface, with flat high-contrast selected endpoints and translucent ribbons; individual days do not become tiny glass cards. Pixel uses square faces and bands, mono typography and the containing panel's registration corners and crisp shadow. No theme moves or scales calendar cells on press. All state changes are immediate, including month replacement; this avoids simulated motion that would misrepresent a date position. Reduced motion has the same stable geometry.

| State           | Presentation and priority                                                                                                                                                          |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rest            | Quiet primary foreground, no individual border or fill.                                                                                                                            |
| Hover           | Ordinary dates receive a quiet neutral tint. A day inside an accepted ribbon receives a local tint of that same accent.                                                            |
| Press           | Press deepens the current role. Ordinary days remain neutral, range interiors remain softly accented and accepted endpoints use the solid accent state tokens with on-accent text. |
| Today           | A short 2px underline beneath the numeral, independent of selection and focus.                                                                                                     |
| Selected        | Solid accent with on-accent text; repeat selection keeps the value.                                                                                                                |
| Focus           | A 2px focus contour, 1px offset, around the specific date, including unavailable dates.                                                                                            |
| Event indicator | Optional 3px current-color dot below the numeral. It conveys information, never availability or selection.                                                                         |
| Unavailable     | Muted crossed-out numeral; hover/focus reveals a reason. Selection is blocked. Existing selection remains recognizable if availability changes.                                    |
| Read only       | Full readable selection and navigable months, no date mutation. A persistent explanation states the restriction.                                                                   |
| Disabled        | Neutral retained selection, disabled foreground, no navigation or tab stops. No whole-component opacity.                                                                           |

Range bands run continuously behind intermediate days. The first endpoint's band starts at its centre, the last ends at its centre. Endpoints are separate solid faces over the band. Week-row continuations end at the row boundary; there are no rounded holes between days. A single-day range has one selected face and no extra band. RTL mirrors the inline geometry and navigation arrows. The optional today underline and event dot remain legible on a solid endpoint.

Keep the accepted dates and band visible until the user confirms a replacement. A valid preview uses an opaque soft accent for its proposed endpoint and a lighter band on added dates. In standalone Calendar, the first date of a new pair stays visible while choosing the second. Give that first date a soft accent when an accepted pair is already present so it reads as part of the draft. The feedback line shows “Preview” and the proposed duration.

When a proposed endpoint would violate a constraint, mark it with the danger tint and give the reason under the grid. A second choice on the same day checks the one-day range. Unavailable days retain their strike. After a rejected selection, its marker and reason remain while pointer or keyboard movement still previews valid alternatives. The preview band follows the candidate before confirmation. A new attempt updates the feedback. A valid choice or dismissal clears it. A selected date retains its accent if it is also the rejected target. A failed choice keeps the accepted range, any first date of a new pair and the field value. Analytical filters may permit unavailable days inside a span. The two endpoints must be available. Minimum and maximum duration count both endpoints.

## Single-date interaction

The field is one plain text input with ordinary selection, copy, paste and caret behavior. There are no spinbutton segments or mandatory character masks. A localized format placeholder distinguishes an empty field from a value. Locale determines numeric day/month ordering and separators; a four-digit year is required. A strict ISO date may be pasted. Normalize a valid local date on blur or Enter, without moving the caret during typing. Never guess a two-digit year or roll February 31 into March.

Tab or pointer focus in the text field does not open the panel. The icon or Alt+ArrowDown opens it at the accepted date, otherwise today clamped to the permitted date interval. Keyboard opening enters the active day; pointer opening leaves the software keyboard closed. Choosing a valid date commits immediately, closes the panel and returns focus to the calendar trigger. Today follows the same commit path. Escape and outside dismissal preserve typed text. The close action returns focus to its trigger; an outside click keeps focus with the clicked destination.

An incomplete or invalid draft remains visible for correction. Show a concrete message on blur or submission, not for every keystroke. Calendar selection can repair the draft. Availability and min/max violations have a different message from parsing errors. A filled optional field can be cleared; its clear action empties it and restores text-input focus. Read only hides clear but permits calendar inspection; disabled blocks both input and trigger and suppresses semantic status. Loading indicates pending work without silently freezing an otherwise editable field. Application status and internal parse errors share Input's status anatomy; internal input errors take priority.

## Range interaction

The field displays two numeric dates separated by a spaced en dash, preserving chronological reading order even in RTL. Clear empties both dates together. A single date is an incomplete draft, never an accepted half-period. Numeric text can scroll within an unusually narrow field. The calendar keeps its usable month width.

- **New or existing period:** open the calendar once and choose two dates. The first choice stays visible in that panel. Pointer or keyboard movement previews the interval. The second valid choice confirms the complete period and closes the panel. Reverse choices are ordered. Choosing the same day twice gives a one-day interval when allowed. Month and year navigation stay available between choices.
- **Opening:** start at the accepted period’s first month or today, within the permitted dates. Keyboard opening enters the day grid. Alt+ArrowDown from either part of the field opens the same calendar. After the first choice, focus stays on that day so arrows can continue to the second.
- **Replacing:** the existing period stays visible in the field and grid until the new pair is complete. Each date can also be edited directly in the text field.
- **Dismissal halfway through:** discard only the unfinished calendar draft and retain the accepted field period. No Apply action is needed.
- **Invalid selection:** keep the panel open and retain the accepted field value and any newly chosen first date. Use the danger tint for the attempted date and explain the availability or duration constraint. Choosing a valid replacement clears the error.
- **Typed reversed dates:** keep the typed order and show “The end date must be on or after the start date.” Do not silently sort user text. Accept complete valid pairs only.

The production parser accepts local dates or ISO endpoints, separated by an en/em dash, a spaced hyphen or `..`. Dirty text retains its parsing locale until accepted or cancelled. Changing locale must not reinterpret a half-entered day/month pair.

## Intended keyboard, focus and form contract

Calendar uses a labelled date grid and one day stop across all visible months. Initial active date follows selection, then today, then an available date in the viewed month. Arrows move by one day/week; horizontal direction mirrors in RTL. Home/End move to the week edges. PageUp/Down move a month, Shift+PageUp/Down a year. Enter/Space selects the focused available day. Unavailable dates remain arrow-reachable with their reason announced and cannot be selected. Read only keeps exploration. Opening either period selector moves focus into its grid. At the first or last page of years, a navigation control that becomes disabled passes focus to the nearest available year. Selection returns focus to days. Escape closes that selector and restores focus to the month or year label before a second Escape can close the picker.

Picker fields keep the visible label attached to their one text input and descriptions/errors programmatically associated. The trigger has an accessible action name, expanded state and panel relationship. Enter in the text field retains ordinary form submission. Focus is never trapped in the nonmodal panel. A valid calendar commit, explicit close and Escape return focus to the trigger; outside dismissal preserves the user's next destination. In forced colors, selected endpoints use Highlight/HighlightText, a proposed endpoint uses a solid Highlight border on Canvas, and interval edges remain visible. Unavailable dates retain their strike and textual explanation.

The shipped API uses timezone-free `YYYY-MM-DD` values (years 0001–9999), not local `Date` objects. The production range value is a complete pair or empty. Production form transport submits ISO values, never localized display text. Invalid or incomplete text disables the relevant ISO carriers, so stale values cannot leak into FormData; range carriers change atomically. Native reset restores the initial accepted value, draft and errors, respects controlled ownership and cancelled reset, and works under disabled fieldsets. Required belongs to validation; empty optional fields remain neutral. Async availability/loading does not clear a selection; a newly unavailable selected date remains visible with validation feedback so the user can repair it.

## Design references

[Primer color usage](https://primer.style/product/getting-started/foundations/color-usage/) defines rest, hover and active by semantic role. Here, the range tint and endpoints retain their role through pointer feedback. [React Aria RangeCalendar](https://react-aria.adobe.com/RangeCalendar) exposes separate range endpoints and availability, which informed the fixed endpoint and candidate treatment. The [GOV.UK date pattern](https://design-system.service.gov.uk/patterns/dates/) supports direct text entry when a date is already known and a calendar when nearby dates or weekdays matter. The [WAI date picker example](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/) informs focus entry and return.

## Inspection and prototype boundary

The three specimens separate sizes/roles, pinned visual states, material panels and live anchored interaction. Pinned feedback examples deliberately keep their supplied status/message; they are not live validation examples. Pinned calendar ranges and focus states remain comparative references. The Live sections implement text correction, clearing, day selection, two-point periods, complete period replacement, range restrictions and dismissal. The collection applies a modified-date interval and an independent verification date cutoff to the result set. The drawer edits one verification date in a local draft and applies it when properties are saved. A calendar selection can repair an invalid date before that save. Panels marked as in-flow keep every theme visible at once and are otherwise interactive. Their source fields sit on a base plate with room for the full value at the default width. Registration resolves separate example and component chunks before first render, following the existing workbench pattern. The floating form uses native top-layer manual popovers so independent workbench samples can coexist; the production dismissal/positioning adapter is designed separately.

The preview uses a deterministic today (September 16, 2026). This is not the runtime default. The parser demonstrates en-GB, en-US and de-DE; it is not a complete international parser. Full IME coordination, arbitrary year bounds, controlled/external updates, native form serialization/reset/validation, complete assistive-technology announcements, month/year roving focus and viewport lifecycle are library implementation work. Their intended user outcomes above are fixed by this design; their technical mechanisms remain open. Any incomplete preview behavior must not be interpreted as an alternate product decision.
